## SKILL: JIRA - JIRA-TASK-CREATION

## PURPOSE
Сформировать и создать задачи в Jira на основании уже проанализированных требований (результата применения Skill requirement-review). Skill предназначен для преобразования анализа требований в задачи разработки и тестирования, готовые к постановке командам.

## INPUTS
Для применения Skill необходимы:
- структурированный результат анализа требований (из Skill requirement-review)
- указание на проект Jira, в котором должны быть созданы задачи
- ссылки на исходные требования (Confluence) или ID требования из анализа (requirement-review) для указания в задачах

Не используй:
- требования, не вошедшие в переданный анализ
- выдуманную функциональность
- устаревшие выводы вместо текущего анализа
- выводы агента вместо исходных требований

Skill не должен самостоятельно искать недостающие входные данные вне пределов переданного контекста.

## PROCEDURE
При создании задач необходимо:
1. определить функциональности, для которых требуются задачи
2. определить гранулярность задач (одна функциональность - одна или несколько задач без излишнего дробления)
3. для каждой задачи сформировать по шаблону (см. Output):
   - заголовок: [Функциональность] - [Действие] - [Результат]
   - описание (что, зачем, ссылка на требование)
   - условия приёмки (Acceptance Criteria)
   - зависимости (если указаны)
   - тип задачи (story/task по настройкам проекта)
   - приоритет по матрице (см. ПРИОРИТИЗАЦИЯ в инструкции агента)
   Примечание: текст [Результат] должен совпадать с [Ожидаемым результатом] тест-кейса Qase для автоматического маппинга.
4. применить правило деривации AC:
   - каждый критерий приёмки требования переносится в задачу, реализующую это требование
   - если AC покрывает несколько задач - каждая задача получает релевантную часть AC
   - если у задачи нет связанных AC - не выдумывать, пометить "AC отсутствуют" и передать агенту на эскалацию для уточнения у владельца продукта
5. проверить дубликаты через поиск в Jira (по совпадению функциональности и заголовка)
6. создать задачу через инструмент создания задачи
7. зафиксировать идентификатор каждой созданной задачи для последующей связи с тест-кейсами
8. при повторном запуске выполнить сверку с ранее созданными задачами (см. ПОВТОРНЫЙ ЗАПУСК в инструкции агента)

## RULES
При создании задач необходимо соблюдать следующие правила:
- не добавлять отсутствующие требования
- каждая задача должна иметь основание в проанализированных требованиях
- не создавать дубликаты
- не выдавать предположения за подтверждённые требования
- не изменять исходные требования
- не изменять и не удалять существующие задачи
- не изменять статусы задач и настройки проекта
- в рамках этого скилла не анализировать требования заново и не создавать тестовую модель в Qase
- не выполнять действия, не относящиеся к созданию задач
- Skill создаёт задачи; подтверждение решений по неоднозначностям - зона агента (эскалация)
- при ошибке внешнего сервиса - повторить попытку до 3 раз, затем остановить этап и сообщить причину

## OUTPUT
Результат Skill должен содержать:
- список созданных задач по шаблону: ID задачи, Тип, Заголовок, Условия приёмки, Зависимости, Ссылка, Связанный ID требования
- подтверждение создания по каждой задаче
- перечень задач, которые не удалось создать, с указанием причины
- связь созданных задач с функциональностями и исходными требованиями (по ID требования)
- записи аудит-лога по каждой задаче (создана/существующая/ошибка)

Результат должен быть структурирован, чтобы следующий этап (создание тестовой модели в Qase) мог использовать его без повторного анализа требований.

## EXAMPLES (ЭТАЛОННЫЙ ПРИМЕР)
Пример созданной задачи:
- ID задачи: AQA-123
- Тип: Story
- Заголовок: Авторизация пользователя - Вход по email и паролю - Пользователь перенаправлен на главную
- Условия приёмки: AC-1 (перенаправление на главную после корректного входа)
- Зависимости: -
- Ссылка: https://jira.example.com/browse/AQA-123
- Связанный ID требования: FR-1

## COMPLETION CRITERIA
Skill считается успешно применённым, если:
- анализ требований получен и использован без повторного анализа
- каждая созданная задача имеет основание в проанализированных требованиях
- каждая задача содержит понятное название, описание и условия приёмки
- дубликаты не созданы
- создание каждой задачи подтверждено
- для каждой задачи сохранён её идентификатор
