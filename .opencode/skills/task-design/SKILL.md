# SKILL: JIRA TASK DESIGN

## PURPOSE

Преобразовать подтверждённые требования из `artifacts/requirement-review.md` в задачи Jira.

## INPUT

Обязательные входные данные:

- `artifacts/requirement-review.md`
- `Quality Gate #1 = PASS`
- Jira project или подтверждённый Jira project context

`Requirement ID` извлекается из `Requirement Review Artifact`.

Источник требований — только `Requirement Review Artifact`.

Не использовать:

- неподтверждённые требования;
- предположения;
- устаревшие версии;
- самостоятельный поиск недостающей информации.

Если обязательные входные данные отсутствуют — `BLOCKED`.

## PROCEDURE

Для каждой функциональности:

- определить необходимые задачи без излишнего дробления;
- сформировать заголовок:
  `[Функциональность] - [Действие] - [Результат]`;
- сформировать описание на основании Requirement Review;
- перенести связанные Acceptance Criteria;
- указать зависимости, если они определены;
- указать тип и приоритет только из переданного контекста;
- указать `Requirement ID`;
- добавить `FR/BR/AC mapping`.

Не изменять смысл исходных требований при формировании задачи.

### Acceptance Criteria

- Каждый AC должен быть связан с соответствующей задачей.
- Если AC относится к нескольким задачам — включить только релевантную часть.
- Если у задачи нет связанных AC — `BLOCKED`, задачу не создавать.
- Не создавать AC самостоятельно.
- Если обязательный AC невозможно однозначно связать с задачей — `BLOCKED`.

### Duplicate Check

Перед созданием:

- выполнить поиск существующих Jira-задач по `Requirement ID`;
- использовать функциональность и заголовок как дополнительные признаки;
- подтвердить найденную задачу через Jira GET;
- при обнаружении соответствующей существующей задачи — не создавать дубликат;
- сохранить её Jira ID и статус `existing`.

Если duplicate check невозможно выполнить:

- установить `BLOCKED`;
- задачу не создавать;
- зафиксировать причину.

### Creation & Verification

- создать задачу через Jira;
- получить созданную задачу через Jira GET;
- проверить:
  - Jira ID;
  - заголовок;
  - Requirement ID;
  - AC;
  - FR/BR/AC mapping;
  - соответствие исходному Requirement Review.

Только после успешной GET-проверки статус задачи — `created`.

Если создание завершилось ошибкой:

- не считать задачу созданной;
- установить статус `error`;
- зафиксировать ошибку.

Если GET verification завершилась ошибкой:

- статус `error`;
- не считать задачу подтверждённой.

## OUTPUT

Для каждой задачи сохранить в `artifacts/jira-tasks.md`:

- Jira ID;
- тип;
- заголовок;
- описание;
- AC;
- зависимости;
- приоритет;
- ссылка;
- Requirement ID;
- FR/BR/AC mapping;
- статус:
  - `created`
  - `existing`
  - `blocked`
  - `error`.

Также зафиксировать:

- результаты duplicate check;
- результаты GET verification;
- ошибки;
- блокировки;
- эскалации.

## RULES

- Не выдумывать требования или AC.
- Не изменять исходные требования.
- Каждая задача должна иметь `Requirement ID`.
- Каждая задача должна иметь основание в Requirement Review.
- Не создавать задачу без AC.
- Не создавать дубликаты.
- Не изменять существующие Jira-задачи.
- Не изменять статусы и настройки проекта.
- Не считать задачу созданной без успешной GET-проверки.
- Не считать существующую задачу подтверждённой без необходимой проверки.
- Не считать duplicate check выполненным, если поиск невозможно выполнить.
- Не анализировать требования повторно.
- Не создавать Qase-тесты.
- Не считать Stage успешным, если существуют нерешённые обязательные `BLOCKED` или `ERROR`.
- Не логировать секреты, токены и credentials.

## COMPLETION CRITERIA

Skill выполнен успешно, если:

- `Quality Gate #1 = PASS`;
- все обработанные задачи имеют `Requirement ID`;
- каждая созданная задача имеет AC и mapping;
- duplicate check выполнен;
- дубликаты не созданы;
- каждая созданная задача подтверждена через Jira GET;
- существующие задачи подтверждены;
- результаты сохранены в `artifacts/jira-tasks.md`;
- `created`, `existing`, `blocked` и `error` разделены;
- отсутствуют нерешённые обязательные `BLOCKED` / `ERROR`.
