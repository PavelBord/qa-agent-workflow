## SKILL: QASE - QASE-TEST-MODEL-CREATION

## PURPOSE
Спроектировать и создать тестовую модель (набор тест-кейсов) в Qase (TMS) на основании проанализированных требований (результата применения Skill requirement-review) и созданных задач Jira (результата применения Skill task-design). Skill предназначен для формирования тестового покрытия, необходимого для проверки описанной функциональности.

## INPUTS
Для применения Skill необходимы:
- структурированный результат анализа требований (из Skill requirement-review)
- список созданных задач Jira с их идентификаторами (из Skill task-design)
- указание на проект Qase и целевой suite

Не используй:
- требования, не вошедшие в переданный анализ
- выдуманные сценарии и ожидаемые результаты
- устаревшие выводы вместо текущего анализа

Skill не должен самостоятельно искать недостающие входные данные вне пределов переданного контекста.

## PROCEDURE
При проектировании тестовой модели необходимо:
1. получить контекст проекта Qase (код проекта)
2. определить и создать структуру тестовой модели (suites по функциональным областям) через инструмент создания suite
3. для каждой функциональности спроектировать тест-кейсы:
   - позитивные (подтверждённое поведение)
   - негативные (только на основании описанных правил валидации)
   - граничные (только при заданных ограничениях)
   - на бизнес-правила и критерии приёмки (только из требований)
4. для каждого тест-кейса сформировать по шаблону (см. Output):
   - заголовок: [Функциональность] - [Действие] - [Ожидаемый результат]
   - описание
   - предусловия (если указаны)
   - шаги
   - ожидаемый результат (только из требований)
   Примечание: текст [Ожидаемый результат] должен совпадать с [Результатом] задачи Jira для автоматического маппинга.
5. связать тест-кейс с функциональностью, требованием (ID) и задачей Jira (ID); если инструмент не поддерживает поле связи - зафиксировать связь в отчёте агента
6. проверить дубликаты через поиск в Qase (по совпадению функциональности, заголовка и сценария)
7. создать тест-кейсы через инструмент создания тест-кейса
8. если тест-кейс создан, но связь с задачей Jira не установилась - повторить попытку связи до 3 раз, затем зафиксировать кейс как "создан без связи" в отчёте
9. при повторном запуске выполнить сверку с ранее созданными кейсами (см. ПОВТОРНЫЙ ЗАПУСК в инструкции агента)

## RULES
При создании тестовой модели необходимо соблюдать следующие правила:
- не добавлять отсутствующие требования
- каждый тест-кейс должен обосновываться требованиями
- не создавать сценарии, которые невозможно обосновать требованиями
- не выдавать предположения за подтверждённое поведение
- не изменять исходные требования
- не изменять и не удалять существующие тест-кейсы
- не удалять Test Run и не изменять результаты пройденных тест-кейсов
- не изменять настройки проекта
- в рамках этого скилла не анализировать требования заново и не создавать задачи в Jira
- не выполнять действия, не относящиеся к созданию тестовой модели
- Skill создаёт тест-кейсы; подтверждение решений по неоднозначностям - зона агента (эскалация)
- при ошибке внешнего сервиса - повторить попытку до 3 раз, затем остановить этап и сообщить причину

## OUTPUT
Результат Skill должен содержать:
- подтверждение создания тестовой модели
- список созданных тест-кейсов по шаблону: ID тест-кейса, Suite, Заголовок, Тип, Шаги, Ожидаемый результат, Связанный ID требования, Связанная задача Jira
- перечень тест-кейсов, которые не удалось создать, с указанием причины
- перечень тест-кейсов, созданных без связи с задачей Jira, с указанием причины
- подтверждение покрытия требований тестовой моделью (метрики покрытия, см. МЕТРИКИ ПОКРЫТИЯ в инструкции агента)
- записи аудит-лога по каждому тест-кейсу (создан/существующий/ошибка)

Результат должен быть структурирован, чтобы обеспечивать прослеживаемость: требование - задача Jira - тест-кейс.

## EXAMPLES (ЭТАЛОННЫЙ ПРИМЕР)
Пример созданного тест-кейса:
- ID тест-кейса: 101
- Suite: Авторизация
- Заголовок: Авторизация пользователя - Вход с валидными email и паролем - Пользователь перенаправлен на главную
- Тип: Functional
- Шаги: 1. Открыть страницу входа. 2. Ввести валидные email и пароль. 3. Нажать "Войти"
- Ожидаемый результат: Пользователь перенаправлен на главную страницу
- Связанный ID требования: FR-1
- Связанная задача Jira: AQA-123

## COMPLETION CRITERIA
Skill считается успешно применённым, если:
- тест-кейсы связаны с анализируемой функциональностью
- обеспечено тестовое покрытие требований
- покрытие измеримо: каждый FR, AC и BR покрыт минимум одним тест-кейсом (доля покрытых FR / общее число FR >= 100%)
- каждый тест-кейс обоснован требованиями
- дубликаты не созданы
- создание тестовой модели подтверждено
- сохранены идентификаторы созданных тест-кейсов и их связь с задачами Jira
