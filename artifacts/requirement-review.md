## 1. Functional Requirements (FR)

| ID | Функциональность | Описание | Источник |
|----|----|----|----|
| FR-01 | Форма авторизации | Система должна предоставлять форму авторизации. Форма должна содержать: поле Email, поле Password, кнопку Login | FR-001 |
| FR-02 | Ввод email | Пользователь должен иметь возможность ввести email | FR-002 |
| FR-03 | Ввод пароля | Пользователь должен иметь возможность ввести пароль | FR-003 |
| FR-04 | Проверка учетных данных | При нажатии кнопки Login система должна проверить введённые учетные данные | FR-004 |
| FR-05 | Успешная авторизация | При успешной авторизации система должна создать пользовательскую сессию и перенаправить пользователя на главную страницу | FR-005 |
| FR-06 | Неверные учетные данные | При вводе неверных учетных данных система не должна создавать пользовательскую сессию | FR-006 |
| FR-07 | Валидация обязательных полей | Система должна отображать сообщение об ошибке при попытке авторизации с незаполненными обязательными полями | VAL-004 |
| FR-08 | Сообщение при неверных данных | При неверном email или пароле система должна отобразить сообщение "Invalid email or password." | ERR-001 |
| FR-09 | Недоступность сервера | При недоступности сервера система должна сообщить пользователю о невозможности выполнить авторизацию | ERR-002 |
| FR-10 | Пребывание на странице авторизации | После неуспешной авторизации пользователь должен оставаться на странице авторизации | ERR-003 |

## 2. Business Rules (BR)

| ID | Правило | Requirement ID | Источник |
|----|----|----|----|
| BR-01 | Поле Email является обязательным для авторизации | FR-02, FR-07 | VAL-001 |
| BR-02 | Поле Password является обязательным для авторизации | FR-03, FR-07 | VAL-002 |
| BR-03 | Email должен соответствовать допустимому формату email | FR-07 | VAL-003 |

---

## 3. Constraints

| ID | Ограничение | Тип | Источник |
|----|----|----|----|
| CONS-01 | Пароль не должен отображаться в открытом виде при вводе | Security | SEC-001 |
| CONS-02 | Система не должна раскрывать, существует ли указанный email в системе, если учетные данные неверны | Security | SEC-002 |
| CONS-03 | Пароль не должен передаваться или храниться в открытом виде | Security | SEC-003 |

## 4. Acceptance Criteria (AC)

| ID | Критерий | Requirement ID | Источник |
|----|----|----|----|
| AC-01 | Пользователь с корректными учетными данными успешно авторизуется | FR-04, FR-05 | AC-001 |
| AC-02 | Пользователь с неверным паролем не авторизуется | FR-04, FR-06 | AC-002 |
| AC-03 | Пользователь с неверным email не авторизуется | FR-04, FR-06 | AC-003 |
| AC-04 | Авторизация без email невозможна | BR-01 | AC-004 |
| AC-05 | Авторизация без пароля невозможна | BR-02 | AC-005 |
| AC-06 | Некорректный формат email обрабатывается системой | BR-03 | AC-006 |
| AC-07 | После успешной авторизации пользователь получает доступ к защищённой части приложения | FR-05, DEP-03 | AC-007 |

## 6. Roles

## 7. AMB (Неоднозначности)

| ID | Описание | Источник | Критичность | Требуемое уточнение |
|----|----|----|----|----|
| AMB-01 | Не определено, на каком этапе выполняется валидация формата email (на клиенте до отправки формы или на сервере) и какое сообщение показывается при недопустимом формате email: сообщение валидации или единое "Invalid email or password." | FR-004, VAL-003, ERR-001, AC-006 | High | Определить место и этап валидации и сообщение для некорректного формата email |

| AMB-03 | Порядок и приоритет проверок не определен: при одновременных ошибках (незаполненные обязательные поля, недопустимый формат email, неверные данные) неясно, какое сообщение отображается первым | VAL-001, VAL-002, VAL-003, VAL-004, ERR-001 | Medium | Определить приоритет валидационных проверок |
